# 멀티플레이 (기획 3차 3)

> 2026-10-04 · 별도 게임 서버 방식. 친구 3명까지 같은 방에서 협동, 빈자리는 봇이 채움.

## 1. 어떻게 돌아가나

```
브라우저 (최대 3명)                          게임 서버 (Node, 1대)
┌──────────────────────┐   명령(Command)    ┌──────────────────────────────┐
│ 화면·HUD·드래그        │ ─────────────────▶ │ 방 관리 (방 코드 4자리)          │
│ RemoteGame            │                   │ 방마다 src/sim 실행 (30Hz)       │
│ (스냅샷을 Game 인터페이스로) │ ◀───────────────── │ 스냅샷 15Hz + 연출 이벤트          │
└──────────────────────┘   스냅샷(상태)      └──────────────────────────────┘
```

- **서버 권위** (R32): 모든 판정은 서버의 sim이 함. 브라우저는 "카드 2를 (x, y)에 놓음" 같은 명령만 보냄.
  - 서버는 명령의 `player`를 **보낸 사람의 자리 번호로 덮어씀**. 남의 캐릭터를 조작할 수 없음.
- 서버는 30Hz로 sim을 돌리고 **초당 15번 스냅샷**(게임 상태 전체 + 그 사이 연출 이벤트)을 보냄.
  - 스냅샷은 sim 내부 값을 빼고 소수점 2자리로 줄인 JSON. 화면에 안 쓰는 값은 줄임 (웨이브 구성은 개수만, 튜닝값은 바뀔 때 + 1초마다, 튜닝 로그는 런이 끝난 뒤에만).
  - 크기: 원본 JSON 평균 6~7KB (몹 30마리면 16KB, 최대 25KB). WebSocket 압축(permessage-deflate) 뒤 실제 전송량은 클라이언트당 **초당 5~13KB** (7장 측정).
- 브라우저는 캐릭터·투사체 위치를 **서버 시각 기준으로 조금 늦게, 스냅샷 사이를 이어서** 그림.
  - 늦추는 시간 = 스냅샷 간격 + 그때그때 잰 도착 흔들림 (보통 약 0.08초, 흔들리는 모바일 망에서는 자동으로 늘어남, 최대 0.35초).
  - 그래서 스냅샷 하나가 늦게 와도 유닛이 멈추지 않음. 그보다 더 늦으면 마지막 속도로 잠깐(0.08초) 이어 감.
- 화면 코드(렌더러·HUD·드래그·보상·결과)는 혼자 하기와 **같은 코드**. 차이는 "내 자리 번호(localPlayer)"뿐.
  - 혼자 하기: 내 자리 = 0, 브라우저 안에서 sim이 돎 (서버 필요 없음).
  - 멀티: 내 자리 = 서버가 알려 준 번호 (방에 들어온 순서).

### 파일

| 경로 | 역할 |

## 2. 플레이 흐름과 규칙

1. **프리셋** → `출발`
   - 게임 서버가 있으면 **매칭 화면**으로.
   - 서버가 없으면 (`vite preview`, 일반 정적 호스팅 등) 프리셋 화면 위에 "게임 서버에 연결할 수 없어요 — 혼자 하기만 가능"이 뜨고 `출발`은 바로 혼자 하기. 서버 확인(`/healthz`)은 한 번만 함 (정적 호스팅이면 404 한 줄이 브라우저 콘솔에 남을 수 있음).
   - 게임 서버가 **응답하지 않으면** (무료 서버가 깨어나는 중, 네트워크 오류, 5xx): 약 3분 동안 3→5→8→10→15초 간격으로 다시 확인 ("서버에 연결하는 중… 무료 서버는 처음 깨어날 때 1분쯤 걸릴 수 있어요"). 그동안 `출발`은 매칭 화면으로 가고 `혼자 하기`도 바로 가능. 3분이 지나도 안 되면 오프라인이지만, `출발`·`다시 시도`가 다시 확인함 (새로고침 필요 없음).
   - **claude.ai 링크(Artifact)**: 처음부터 혼자 하기 전용 빌드. 서버 확인도 연결 시도도 하지 않음 (콘솔 에러 0). 프리셋 화면 안내는 "혼자 하기 전용 링크 · 멀티는 게임 서버 주소에서" (봇 2명과 혼자 하기).
2. **매칭 화면** (R30)
   - 닉네임 (최대 12자, 이 기기에 기억). 비우면 서버가 `플레이어N`을 붙임.
   - `혼자 하기` (봇 2명) · `방 만들기` · `코드로 참가` (4자리) · 열린 방 목록 (탭해서 참가).
   - 게임 중인 방은 목록에 "게임 중"으로 보이지만 들어갈 수 없음 (R31).
3. **방 화면**
   - 큰 방 코드 → 친구에게 알려 주기. 슬롯 3칸에 닉네임 + 캐릭터 3 + 펫 3. 빈칸은 "빈자리 → 봇".
   - `시작`은 **방장만**, 혼자여도 언제든 가능. 빈자리는 봇(BOT 1, BOT 2)이 채움.
   - `프리셋 변경` → 프리셋 화면으로 갔다가 `출발`을 누르면 방에 그대로 돌아옴 (편성만 바뀜).
   - 방장이 나가면 다음 사람이 방장 (방 이름 "○○의 방"도 새 방장 이름으로). 모두 나가면 방이 사라짐.
4. **전투**
   - 좌상단에 **다른 두 플레이어** (사람 이름 또는 BOT). 연결이 끊긴 사람 자리는 이름 옆에 작은 `BOT` 표시.
   - **일시정지 없음** (R35). 톱니 버튼은 "메뉴": 닫기 / 디버그(방장만) / 전체 화면 / 나가기.
   - **디버그 패널은 방장만** 보이고, 바꾼 값은 모두에게 적용. (멀티에서 바꾼 값은 이 기기의 혼자 하기 설정에 저장되지 않음)
5. **층 보상** (R33)
   - 사람마다 자기 보상 3개 중 1개를 고름. 봇은 바로 고름.
   - 고른 사람은 "다른 플레이어 선택 대기 중 (n/3)". **20초**가 지나면 아직 안 고른 사람은 무작위.
6. **나가기 / 연결 끊김** (R34)
   - 방장이 아닌 사람이 `나가기` → 매칭 화면으로. 그 자리는 봇이 런 끝까지 이어서 함.
   - 방장이 `나가기` → **모두의 런이 끝남** → 결과 화면.
   - 연결이 끊기면 그 자리는 봇이 대신 조작. **같은 브라우저로 다시 접속하면**(새로고침, 탭을 닫았다가 링크 다시 열기 포함) 바로 전투 화면의 자기 자리로 돌아와 이어서 조작.
   - **조용한 끊김** (터널·엘리베이터: 소켓은 열린 채 아무것도 안 옴): 1.5초 동안 스냅샷이 없으면 "연결이 불안정해요 · 다시 연결하는 중…" 배너 + 교체·펫·궁극기·보상 선택을 거절 (조용히 삼키지 않음). 5초가 지나면 소켓을 새로 열어 같은 토큰으로 다시 접속 (기기가 오프라인으로 알려진 동안은 접속 시도 없이 기다렸다가 신호가 돌아오는 즉시 접속 → 측정: 0.2~0.7초 만에 다시 조작). 서버는 5초마다 핑을 돌려 응답 없는 소켓을 5~10초 안에 끊고 그 자리를 봇에게 넘김.
   - 늦게 도착한 교체·펫 명령 (기준 스냅샷이 2초보다 오래됨, `cmd.atTick`)은 서버가 "연결이 늦어 취소됐어요"로 거절 → 끊김 뒤에 옛 위치로 교체되는 일 없음.
   - **같은 접속 토큰을 가진 탭이 둘** (브라우저의 "탭 복제" 등): 나중 탭이 자리를 가져가고, 이전 탭은 다시 접속하지 않고 멈춤 → 매칭 화면에 "다른 탭에서 접속 중이에요 · 이 탭은 멈췄어요" + `여기서 계속` (누르면 이 탭이 자리를 되찾고 다른 탭이 멈춤). 서로 끝없이 밀어내지 않음.
7. **결과** → `방으로` (방장이 다시 시작 가능) / `방 나가기`
   - 런이 끝나고 약 5초 뒤 방은 다시 "대기 중"이 됨. 그때까지 돌아오지 않은 사람은 방에서 빠짐.

## 3. 내 컴퓨터에서 테스트

```bash
npm install          # 처음 한 번
npm run build:all    # 클라이언트(dist/) + 서버(dist-server/) 빌드
npm start            # http://localhost:8080
```

- 브라우저 **탭 3개**로 http://localhost:8080 을 열면 3명으로 테스트할 수 있음 (탭마다 다른 플레이어).
- 같은 와이파이의 폰: `http://<PC의 IP>:8080` (예: http://192.168.0.10:8080). 방화벽에서 8080 허용 필요.
- 개발 모드 (코드 고치면 바로 반영):
  ```bash
  npm run dev:server   # 게임 서버 :8787
  npm run dev          # 화면 :5173 (/ws, /healthz 는 :8787로 넘겨 줌)
  ```
  - `npm run dev`만 켜면 혼자 하기만 됨 (콘솔 에러 없음). 나중에 게임 서버를 켰으면 매칭 화면의 `다시 시도`.
- claude.ai에 올릴 혼자 하기 전용 파일: `npm run build:artifact` → `dist-artifact/index.html`.
- 서버 옵션 (환경 변수): `PORT` (기본 8080), `HOST` (기본 0.0.0.0), `STATIC_DIR` (기본 `dist`), `DEBUG_NET=1` (5초마다 스냅샷 크기 로그).
  - 서버 전체 제한: `MAX_GAMES` (동시에 돌아가는 게임 수, 기본 20 → 넘으면 방장에게 "서버가 붐벼요 · 잠시 뒤에 다시 시작해 주세요"), `MAX_CONNECTIONS` (소켓 수, 기본 300), `MAX_CONNECTIONS_PER_IP` (주소당 소켓, 기본 16). 넘는 접속은 연결 단계에서 503 → 브라우저가 점점 길게 기다리며 다시 시도.
  - `TRUST_PROXY=1`: 프록시 뒤(Render)에서 주소당 제한이 `X-Forwarded-For`의 첫 주소를 씀.

## 4. Fly.io에 올리기 (추천)

- 이미 있는 `Dockerfile`과 `fly.toml`을 그대로 씀. 서버 지역은 **도쿄(nrt)** → 한국에서 핑이 낮음.
- 아무도 없으면 머신이 멈추고(요금 절약), 다음 접속 때 **몇 초 만에** 다시 켜짐 (Render 무료처럼 1분 기다리지 않음).
- **요금**: 새 계정은 무료 사용량이 없음. 체험판(머신 2시간 또는 7일) 뒤에는 카드를 등록하고 쓴 만큼 냄. 가장 작은 머신(shared-cpu-1x, 256MB)이라 켜져 있는 시간만큼만 소액. 정확한 금액은 https://fly.io/docs/about/pricing/ 확인.
- **머신은 꼭 1대**: 방 정보가 서버 메모리에 있어서 2대가 되면 방 목록이 갈라짐. 그래서 배포할 때 항상 `--ha=false`.
- **배포·재시작하면 열려 있던 방은 모두 사라짐.**

### 준비 (공통)

1. https://fly.io 가입 → 카드 등록 (체험판이 끝나면 필요).
2. `fly.toml` 맨 위의 `app = "swap-tower-zerocoke8"`이 앱 이름 (원하면 **나만의 이름**으로 바꾸기) (영어 소문자·숫자·하이픈, 전 세계에서 하나뿐이어야 함). 게임 주소가 `https://<이름>.fly.dev`가 됨.
   - GitHub 웹에서 `fly.toml`을 열고 연필 아이콘으로 고쳐도 됨.

### 방법 A: 내 컴퓨터에서 명령어로

```bash
# 1) flyctl 설치
#    macOS:   brew install flyctl
#    Windows: PowerShell에서  iwr https://fly.io/install.ps1 -useb | iex
#    Linux:   curl -L https://fly.io/install.sh | sh
fly auth login                       # 브라우저로 로그인

# 2) 저장소 받기 (처음 한 번)
git clone https://github.com/zerocoke8/Lt_test1.git
cd Lt_test1
git checkout claude/design-notes-v0  # main에 합친 뒤라면 main

# 3) 앱 만들기 (처음 한 번) — 이름은 fly.toml의 app 값과 같게
fly apps create <앱이름>

# 4) 배포 (빌드는 Fly 서버에서 함, 내 컴퓨터에 Docker 필요 없음)
fly deploy --ha=false
```

- 끝나면 `https://<앱이름>.fly.dev`를 열어서 확인 → 친구들에게 공유.
- 혹시 머신이 2대가 됐다면: `fly scale count 1`.
- 도쿄 리전이 없다는 오류가 나면: `fly platform regions`로 목록을 보고 `fly.toml`의 `primary_region`을 가까운 곳(예: `hkg`, `sin`)으로 바꾸기.
- 로그 보기: `fly logs` · 상태: `fly status`.

### 방법 B: 컴퓨터 없이 GitHub에서 (Actions)

`.github/workflows/fly-deploy.yml`이 Fly에 배포해 줌. 버튼을 눌렀을 때만 돎 (푸시마다 돌지 않음).

1. Fly 토큰 만들기: Fly 대시보드의 **Tokens** 메뉴에서 조직(Org) 토큰 생성, 또는 컴퓨터에서 `fly tokens create org`. 화면 이름은 바뀔 수 있음.
   - 앱을 이미 만들었다면 그 앱 전용 배포 토큰(`fly tokens create deploy`)도 됨.
2. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret** → 이름 `FLY_API_TOKEN`, 값 = 토큰.
3. GitHub 저장소 → **Actions** 탭 → 왼쪽 **Fly 배포** → **Run workflow**.
   - 앱이 없으면 `fly.toml`의 이름으로 만들고, 머신 1대로 배포함.
   - 끝나면 실행 결과 요약에 게임 주소가 나옴.
4. 그다음부터는 **자동 배포**: 이 브랜치(`claude/design-notes-v0`, 또는 `main`)에 게임 코드(`src/`, `server/`, 빌드 설정, `fly.toml` 등)가 바뀐 커밋이 푸시되면 Actions가 알아서 배포함. 3~5분 뒤 주소에 반영.
   - 문서·테스트·스크린샷만 바뀐 푸시는 배포하지 않음 (배포하면 서버가 재시작되어 열려 있던 방이 사라지기 때문).
   - 이미 열어 둔 게임 화면은 배포 중 연결이 끊김 → **새로고침**하면 새 버전.
   - 수동으로 다시 배포하고 싶으면 3번 (Run workflow).

### Fly 설정 요약 (`fly.toml`)

| 항목 | 값 | 이유 |
|---|---|---|
| `primary_region` | `nrt` (도쿄) | 한국에서 가까움 |
| `internal_port` | 8080 | 서버 기본 포트 |
| `auto_stop_machines` / `min_machines_running` | `stop` / 0 | 아무도 없으면 멈춤 → 요금 절약. 접속하면 자동으로 켜짐 |
| `TRUST_PROXY` | `fly` | 접속 수 제한에 Fly가 넣는 `Fly-Client-IP`를 씀 (위조 불가) |
| `MAX_GAMES` | 3 | 게임 1판 ≈ 코어의 3% → 작은 머신에서 동시 3판까지 |
| `[[vm]]` | shared-cpu-1x, 256MB | 측정: 대기 72MB, 게임 3판 74MB |
| 헬스 체크 | `/healthz` | |

## 5. Render에 올리기 (무료, 다른 방법)

준비: 이 저장소가 GitHub에 있어야 함. 브랜치는 `claude/design-notes-v0` (main에 합친 뒤라면 `main`).

### 방법 A: Blueprint (render.yaml 사용, 추천)

1. https://render.com 가입 → **GitHub 계정 연결**.
2. 대시보드 → **New +** → **Blueprint**.
3. 저장소 선택 → 브랜치 `claude/design-notes-v0` (또는 `main`) 선택.
4. `render.yaml`을 읽어서 `swap-tower` 웹 서비스가 보임 → **Apply**.
5. 빌드 (`npm ci --include=dev && npm run build:all`) 가 3~5분 걸림. 끝나면 서비스 페이지 위쪽의 주소 (예: `https://swap-tower.onrender.com`).
6. 그 주소를 친구들에게 공유. 각자 프리셋 → 출발 → 매칭.

### 방법 B: 직접 설정

New + → **Web Service** → 저장소/브랜치 선택 후:

| 항목 | 값 |
|---|---|
| Runtime | Node |
| Build Command | `npm ci --include=dev && npm run build:all` |
| Start Command | `npm start` |
| Instance Type | Free |
| Health Check Path | `/healthz` (Advanced) |

- 포트는 Render가 `PORT`로 알려 주고 서버가 그대로 씀. 따로 설정할 것 없음.
- `render.yaml`은 `TRUST_PROXY=1`, `MAX_GAMES=3`을 넣음: 무료 플랜은 CPU 0.1개라서 게임 1판(코어의 약 3%)을 3판까지만 동시에 돌림. 방법 B(직접 설정)라면 Environment에 같은 값을 넣기. 유료 플랜이면 `MAX_GAMES`를 올리면 됨.
- `autoDeploy`가 켜져 있으면 그 브랜치에 푸시할 때마다 다시 배포됨. **배포·재시작하면 열려 있던 방은 모두 사라짐.**

### 무료 플랜 주의

- 한동안(약 15분) 아무도 접속하지 않으면 서버가 **잠듦**. 다음 첫 접속은 깨어나느라 **1분쯤** 걸림 (페이지가 늦게 뜸). 페이지가 뜬 뒤에는 정상 속도.
- 첫 사람이 먼저 주소를 열어서 서버를 깨워 두면 편함.
- 서버가 있는 지역(render.yaml: 싱가포르)에 따라 핑이 달라짐. 매칭 화면 오른쪽 위에 핑(ms)이 보임.

### Docker로 올리기 (다른 호스팅)

```bash
docker build -t swap-tower .
docker run -p 8080:8080 swap-tower
```

`multi` 흐름 (3명: 에이=방장, 비, 씨):
1. 매칭 → 방 만들기 → 코드로 참가 / 목록에서 참가 → 방장이 시작. 각자 다른 자리(localPlayer 0/1/2).
2. 비가 **블레이드(오른쪽 돌진)** 카드를 실제로 끌어서 들고 있는 동안: 미리보기(돌진 경로·도착 지점)는 **비의 화면에만**, 에이·씨의 화면엔 없음 (`multi-drag-preview-b.png`).
3. 놓으면 에이·씨의 화면에도 같은 돌진(오른쪽, 놓은 지점에서 시작)이 그려짐 (`multi-dash-a.png`). 씨의 **거너(왼쪽 부채꼴)**도 에이·비 화면에 왼쪽 방향 그대로 (`multi-cone-a.png`).
4. 층 보상: 세 명이 각자 고름, "다른 플레이어 선택 대기 중 (n/3)" (`multi-reward-wait.png`).
5. 비의 탭이 닫힘 → 비 자리에 BOT 표시 (`multi-bot-tag.png`) → 비가 같은 기기에서 링크를 다시 열면 바로 자기 자리로 복귀, 실제 드래그로 교체까지 (`multi-reconnected-b.png`).
6. 씨가 나가기 → 씨 자리는 봇. 방장이 나가기 → 모두 결과 화면 (`multi-result.png`) → 방으로.
7. 방장(에이)이 방을 나감 → 비가 방장, 방 이름 "비의 방", 시작 버튼 (`multi-host-handoff.png`) → 비가 시작.
- 따로: 1명 방(방장 + 봇 2), 게임 중 새로고침 → 같은 자리로 복귀.
- 조용한 끊김: 비의 폰이 오프라인(소켓은 열린 채) → 4초 안에 배너 + 교체 거절 (`multi-stall-b.png`), 에이 화면에서 비 자리가 약 6초 만에 BOT, 신호가 돌아오면 1초 안에 비가 다시 조작. 끊긴 순간 끌어 놓은 교체는 나중에 옛 위치로 적용되지 않음.
- 탭 복제: 같은 토큰의 두 번째 탭이 자리를 가져가고 첫 탭은 멈춤("다른 탭에서 접속 중", `multi-replaced-tab.png`), 몇 초 지나도 그대로 → `여기서 계속`으로 되찾음.
- `npx vitest run tests/net`: 위 서버 테스트 + 연결(`connection.test.ts`: 4001에서 멈춤, 조용한 소켓 교체, 정적 호스트 1번만 확인, 응답 없는 서버는 계속 확인) + 서버 제한(`server-limits.test.ts`: 늦은 명령 거절, 소켓·주소·동시 게임 제한, 파티 안 중복 캐릭터 거절, 5초 핑).

## 7. 측정 (2026-10-04, 이 PC: 4코어, 헤드리스 Chromium 3개 + 서버가 같은 기계)

폰 화면(844×390@3x) 브라우저 3개가 한 방에서 플레이 (각자 교체·펫·궁극기). 서버 앞에 바이트 세는 프록시를 두고 실제 전송량을 잼.

| 상황 | 스냅샷 원본 JSON | 실제 전송 (압축 뒤, 클라이언트당) | 화면 fps (3개 각각) | 프레임당 JS | 서버 CPU |
|---|---|---|---|---|---|
| 일반 (1~2층, 엔티티 ≤ 10) | 평균 6~7KB, 최대 9KB (≈100KB/s) | **4.6KB/s** | 59.7~59.8 | 평균 1.4~1.9ms | 코어 1개의 3% |
| 스트레스 (몹 30마리, 엔티티 31) | 평균 16KB, 최대 25KB (≈250KB/s) | **13KB/s** | 57.7~58.0 | 평균 3.3~4.0ms (p95 13ms) | 코어 1개의 3% |

- 압축(permessage-deflate, 연결마다 앞 내용을 기억)이 스냅샷을 약 20분의 1로 줄임. 모바일 데이터로도 부담 없는 크기.
- 스냅샷 줄이기 전/후 (같은 시드, 서버 없이 sim만): 일반 평균 8.4 → 7.2KB, 스트레스 최대 26.3 → 24.5KB. 압축 뒤 크기는 거의 같음 (압축이 원래 잘 되던 부분).
- 원본이 30KB를 넘지 않아서 더 줄이지 않음 (필요하면: 기본값 필드 생략, 엔티티 배열을 짧은 키로).

## 8. 한계 (프로토)

- **서버 1대, 메모리 보관**: 서버가 재시작·재배포되면 방과 진행 중인 게임이 사라짐. 저장·랭킹·계정 없음.
- **지연 보정 없음**: 카드를 놓으면 서버 왕복(핑) 뒤에 결과가 보임. 국내↔싱가포르 기준 대략 0.1초 안팎. 교체 손맛 검증은 혼자 하기가 더 정확함.
- 화면 위치는 서버보다 약 0.08초(흔들리는 망에서는 최대 0.35초) 늦게 그림. 연출 이벤트(피해 숫자 등)와 HP는 받자마자 보여서 위치보다 아주 조금 먼저 보일 수 있음.
- 서버 한 대가 동시에 돌리는 게임 수에 제한이 있음 (`MAX_GAMES`, Render 무료는 3판).
- 재접속은 **같은 브라우저**에서만 (접속 토큰을 브라우저 저장소에 둠). 다른 기기로 이어서 할 수는 없음.
- 방장이 게임 중 **연결만 끊기면**(나가기 아님) 방장은 그대로라서 그 런 동안 디버그 패널을 쓸 사람이 없음. 런이 끝나면 돌아오지 않은 방장은 방에서 빠지고 다음 사람이 방장.
- 휴대폰에서 다른 앱으로 오래 나가면 연결이 끊겨 봇이 대신함. 돌아오면 자동으로 다시 붙음.
- 게임 중인 방에는 새로 들어갈 수 없음 (끝나고 "대기 중"이 되면 가능).
- 같은 닉네임·같은 캐릭터 중복 허용. 비밀번호 방, 강퇴 없음.
- 디버그·튜닝은 방장 한 명이 모두에게 적용. 멀티 튜닝 값은 저장되지 않음 (게임마다 기본값).
- claude.ai 링크(Artifact)는 외부 서버 연결이 막혀 있어 **혼자 하기만** 가능.
